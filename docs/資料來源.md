## `kisegae:` — Kisegaeningyou

- **來源**：<https://github.com/hayde0096/Kisegaeningyou>（public，預設分支 `main`）
- **取得日期**：2026-09-22
- **內容**：同一角色的換裝集。`images`～`images5` 五個目錄共 430 組
  `<timestamp>.png` 與 `<timestamp>.png.desc.txt`，desc 是逗號分隔的服裝 tag 列表。
- **匯入程式**：[`scripts/pipeline/kisegae.py`](../scripts/pipeline/kisegae.py)

### 授權狀態

**該 repo 沒有 LICENSE 檔，也沒有 README。** 未標示授權在法律上的預設是保留所有權利。
本專案因此採取不重新散布的做法：

- **tag 文字**：不逐字收錄。每套造型經 Gemini 重新詮釋成繁體中文的 `title` 與
  `description`（供語意檢索），`prompt_snippet` 只保留服裝相關的英文 tag。
- **圖片**：**一張都不進本 repo**，不轉檔、不做縮圖、不上傳任何儲存空間。
  `image_url` 直接指回上游 raw URL，由使用者的瀏覽器向上游請求。

### 署名機制

署名不能只躺在這份文件裡——要在圖片**被使用的當下**出現。實作要求（子專案 2 前端／API）：

> 顯示 `image_url` 時，依 `source_ref` 前綴一併顯示出處連結。
> `kisegae:` → <https://github.com/hayde0096/Kisegaeningyou>
> 對應常數見 `pipeline/kisegae.py` 的 `SOURCE_REPO`。

現況（2026-09-25）：知識庫的圖或片段出現在畫面上的三個地方都標出處，讓使用者一眼看出內容屬於原作者。

- **preset 抽屜**：圖片正下方、標題之前一個說明框，依前綴說明來源與「著作權屬原作者；本服務只連結、不轉存」
  （`kisegae:` 另註明上游未標示授權；前綴不認得時退回通用的一句），有出處頁面時後面接「查看原頁 →」
  另開分頁。圖載入失敗或沒有圖時說明框照樣顯示——片段文字一樣屬於原作者。
- **工具卡縮圖列**：列上方一行「圖片來自來源網站，著作權屬原作者，點圖看出處」；每張縮圖右下角疊來源名
  標籤（Civitai／Kisegaeningyou），前綴不認得或「無圖」佔位不加。
- **定稿卡 rag chip**：滑過的提示是「來自〈片段標題〉（Civitai）」，前綴不認得時不加括號。

資料面：`GET /api/presets/{id}` 回 `sourceRef` 與伺服器算好的 `sourceUrl`
（`src/PromptCopilot.Api/Data/SourceAttribution.cs`，子專案 4 起）。`tool_result` 事件的每筆 preset、
定稿的 `positiveSources`／`negativeSources`（`TagSource`，rag 取第一個命中片段的）也帶 `sourceRef`。
前綴 → 來源名與說明文字在前端 `lib/copy.ts` 的 `sourceName`／`sourceNotice`；出處網址只由伺服器算。

### 已知的取捨

- **圖是 1024×1536 原圖**（約 1MB）。因為不轉存所以無法縮圖，預覽抽屜一次載 5 張約 5MB。
- **相依於上游存續**。上游若下架或改檔名，`image_url` 會 404。這與 `civitai:` 紀錄
  指向 `image.civitai.com` 是同一種曝險，不是新增的。
- **逃生門**：`image_url` 是純 TEXT 欄位。日後若取得授權要自架，一次 UPDATE 加搬檔即可，
  不動 schema。

### 匯入結果（2026-09-22 實跑）

掃到 378 筆，**寫入 377 筆**。少的那一筆是正當去重：來源裡兩個 desc 是同一套造型，
只差權重寫法（`kisegae:1741156656403` 撞到 `kisegae:1741125652372`）。

候選池變化（`coverage_report.py` 前後對照）：

| clothing.material | 114 | **228** |

| clothing.lower | 741 | 1,038 |
| clothing.accessories | 951 | 1,242 |

檢索驗收（實測，非推估）：對「穿著深灰色磨損落肩皮夾克，內搭黑色連帽衫」這種
**具體衣著描述**，kisegae 片段拿到第 1 與第 3 名（距離 0.200／0.231）。對
「想要有中世紀騎士感」「時尚現代的潮流服飾」這類抽象查詢則全數由 civitai 勝出——
那是使用者**沒**描述穿著時才會產生的推想查詢，命中只進建議、不會寫進提示詞，
輸在那裡的代價低。

### 兩個與原設計不同的實際行為

1. **`prompt_snippet` 的權重語法被模型正規化掉了。** 原始 desc 有 76 筆含 `(x:1.1)`，
   產出的 snippet 只剩 3 筆保留。原本的設計是「保留原樣、與既有語料一致」，實際沒做到。
   不打算改回來：權重是為原本那張圖調的，借進別人的提示詞等於帶了個任意強調值。
2. **description 的寫法試過兩版。** 第一版要求「描述質感、場合與氛圍」，實跑 20 筆發現
   模型 5/6 筆以「散發…氣息的…適合…」開頭——既有 1,980 筆 Clothing 片段沒有任何一筆
   這樣寫。句型雷同會讓 377 筆的向量擠在一起，也對不上使用者逐字描述衣著時的子查詢。
   改成要求「講穿的是什麼：款式、顏色、材質」後，最常見句首從 ~83% 降到 20%。
   細節見 `tests/test_kisegae.py::test_build_prompt_demands_concrete_garment_description`。

### NSFW 過濾

這批資料用的是**收窄過的**關鍵詞清單（`pipeline/kisegae.py` 的 `CLOTHING_SAFE_WORDS`），
不是 `pipeline/nsfw_filter.py` 的完整清單——後者維持原樣，civitai 路徑的判準不變。

放寬的只有「性暗示形容詞」那一層加上 `lingerie`／`see-through`／`underwear only`：
對服裝語料而言，一整套造型不該因為單一個 `cleavage` 被丟掉。解剖學名詞與性行為詞照擋。

實測結果：430 筆 → **保留 378 筆**（完整清單只會留下 284 筆）。被擋下的 52 筆確實含
`nude`、`nipples`、`topless`、`bottomless`、`pussy`、`bondage` 等 tag。

連帶損失：danbooru 的 `naked <衣物>` 慣例（`naked apron`、`naked poncho`、`naked tabard`
等，意思是「只穿這件」）也一併被擋，約 25 筆。為它們加白名單不划算，接受這個損失。

## 公開散布與免責聲明

`docker compose up` 首次啟動會從 GitHub Release（tag `seed-v1`，資產 `prompt_copilot_seed_v1.dump`）
下載知識庫種子灌進資料庫。這份 dump 由 `scripts/export_seed.py` 匯出，只含 `prompt_knowledge_presets`
與 `shared_prompt_histories` 兩張表的資料（`pg_dump --data-only`），不含 schema、不含 `audit_logs`。

| 項目 | 2026-09-24 匯出（v1） |
| :--- | ---: |
| presets（civitai） | 18,977 |
| presets（kisegae） | 377 |
| histories（civitai） | 6,294 |
| embedding | `gemini-embedding-001`，768 維 |
| 壓縮後大小 | 約 104 MB |

1. 種子是 Civitai 公開 API 與 Kisegaeningyou 的**衍生物**：原始 prompt 經 Gemini 重新詮釋為繁中描述與
   結構化片段，不是逐字轉載。
2. **圖片一律不轉存**：dump 只含指向上游的 URL，由使用者瀏覽器向上游請求；上游下架即失效。
3. Kisegaeningyou 上游**未標示授權**，`prompt_snippet` 保留了上游的服裝英文 tag；本專案以署名
   （產品內出處連結＋本文件）與非商業用途為據收錄。
4. 本專案為**非商業求職作品集**用途；來源方或權利人提出要求即移除對應資料並重發 dump。
5. dump 的授權狀態**不等於**程式碼的 MIT：repo 的 `LICENSE` 只涵蓋程式碼與文件，不涵蓋 Release 資產。
6. 使用者透過「存進共享知識庫」寫入的紀錄（`source = 'user'`）不在公開 dump 裡，匯出時已刪除。

換 embedding 模型或維度時，dump 版本號 +1，`db/init/001_schema.sql` 的 `VECTOR(768)` 與
`docker-compose.yml` 的 `SEED_URL` 預設值一起改；舊 dump 灌進新 schema 會在 `pg_restore` 階段失敗，不會靜默出錯。
