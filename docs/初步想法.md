# GenAI Prompt Copilot 專案規格與實作計畫書

---

## 一、 專案定位與核心目標

本專案旨在建構一個具備**自我演化共享知識庫**、**五維度充足度主動引導**與**嚴格合規過濾**的 AI 生圖提示詞（Prompt）協作助理。系統透過多輪對話協助使用者精煉生成式圖片的提示詞，主動識別並建議缺失細節，並在定稿後經使用者同意沉澱為全域共享知識。

### 職缺技術對位亮點
* **Semantic Kernel (C#)**：實作核心 AI 編排，涵蓋 Plugins (Tool Calling)、Filters (Guardrails & Audit) 與 RAG。
* **ASP.NET Core Web API**：負責系統後端服務、Session 狀態機管理與提供 RESTful/SSE 串流介面。
* **Nuxt 3 (Vue 3)**：建構具備現代感與打字機串流效果的前端應用介面。
* **PostgreSQL + pgvector**：以單一資料庫同時支援關聯性資料與向量相似度檢索（含多標籤 GIN 索引與多模態圖片連結）。
* **Python 工具鏈**：離線資料爬取、清洗與批次向量化注入管線。
* **GitHub Actions & Azure**：建立自動化 CI/CD 流水線與雲端容器化部署架構。

## 二、 核心互動流程與系統功能

### 1. 系統互動流程圖

```text
[使用者輸入生圖需求]
        │
        ▼
 1. 安全合規過濾 (SK Filter: 攔截 NSFW、真實公眾人物姓名)
        │
        ▼
 2. 共享記憶檢索 (RAG 1: 向量庫找出 Top-3 全域相似 Prompt 作為參考)
        │
        ▼
 3. 五大維度充足度分析 (LLM 分析: 風格 / 場景 / 鏡頭 / 樣貌 / 穿著)
    ├── 資訊不足 ──► 4. 領域知識推薦 (Tool Call / RAG 2: 查詢多標籤預設庫)
    │                     │ (單一任務最多追問 2 輪；或使用者要求「直接補齊」)
    │                     ▼
    └── 資訊充足 ──► 5. 輸出最終提示詞 (正向詞、負向詞、生成建議)
                          │
                          ▼
                     6. 入庫詢問確認 (前端跳出提示：「是否儲存至共享知識庫？」)
                          ├── 使用者拒絕 ──► 流程結束
                          └── 使用者同意 ──► 7. 資料庫持久化與向量閉環 (寫入 DB 並存入 RAG 1)
```

### 2. 五大維度充足度檢驗 (Sufficiency Check)
系統非單純檢查欄位「有無」，而是評估其「**資訊顆粒度是否足夠產生高畫質圖像**」：

| 維度 | 評估標準 | 不足範例（觸發引導） | 充足範例（通過檢驗） |
| :--- | :--- | :--- | :--- |
| **風格 (Style)** | 是否具備明確藝術流派、渲染引擎或畫師風格 | 「好看的插畫」 | 「新海誠動畫光影風格、Makoto Shinkai style, vibrant colors」 |
| **場景 (Scene)** | 是否包含環境結構、氣候、空間光源與背景細節 | 「在房間裡」 | 「昏暗雜亂的賽博朋克單人公寓，窗外有細雨與閃爍霓虹招牌」 |
| **鏡頭 (Camera)** | 是否明確指定視角、焦段或景深 | 「正面看著」 | 「低角度仰拍 (low angle shot)、85mm 人像鏡頭、淺景深 (shallow depth of field)」 |
| **人物樣貌 (Appearance)** | 是否有具體的年齡、髮型、五官特徵與眼神情緒 | 「一個男生」 | 「20歲初頭亞裔青年、凌亂微捲黑髮、帶有疲憊冷峻的眼神」 |
| **人物穿著 (Clothing)** | 是否指定衣著款式、材質、顏色與磨損質感 | 「穿著外套」 | 「穿著深灰色磨損落肩皮夾克，內搭黑色連帽衫，金屬拉鍊反光」 |

> **動態開關機制**：若使用者需求為風景、載具或抽象靜物，LLM 自動關閉「人物樣貌」與「人物穿著」檢核，避免無效追問。

### 3. 防死循環機制 (Anti-Stalling Multi-Turn Policy)
* **輪次計數硬上限**：單一 Prompt 調優流程最多允許 **2 輪** 主動提問。超過 2 輪時，LLM 強制啟用自動補全，直接產出最佳實踐提示詞。
* **捷徑指令**：若使用者提及「隨便」、「幫我決定」、「你看著辦」或直接確認，LLM 立即跳過後續追問，自行補齊細節定稿。

### 4. 共享入庫確認機制
* 定稿提示詞產出後，前端彈出確認卡片：「*提示詞已產出！是否同意將此提示詞與描述沉澱至全域共享知識庫？*」
* 使用者確認後，前端觸發專用持久化 API（或透過對話確認由 LLM 調用 Tool），將資料寫入 PostgreSQL 並即時向量化。

## 四、 資料庫模型設計 (PostgreSQL + pgvector)

### 1. 共享生成歷史表 (`shared_prompt_histories`)
儲存使用者確認沉澱的提示詞紀錄，作為全域 RAG 1 檢索來源。

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE shared_prompt_histories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_intent TEXT NOT NULL,                  -- 使用者原始自然語言描述
    positive_prompt TEXT NOT NULL,              -- 英文正向提示詞
    negative_prompt TEXT NOT NULL,              -- 負向提示詞
    completeness_scores JSONB,                  -- 五維度評估紀錄 (JSON)
    intent_embedding VECTOR(768),               -- Gemini Embedding 向量 (768 維)
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_shared_intent_embedding 
ON shared_prompt_histories 
USING hnsw (intent_embedding vector_cosine_ops);
```

### 2. 生圖風格與標籤知識包 (`prompt_knowledge_presets`)
儲存支援多標籤、模糊敘述與預覽圖片的知識包，供 Tool Calling 與 RAG 2 檢索。

```sql
CREATE TABLE prompt_knowledge_presets (
    id BIGSERIAL PRIMARY KEY,
    title VARCHAR(100) NOT NULL,               -- 預設名稱 (如: 賽博龐克雨夜)
    category VARCHAR(50) NOT NULL,              -- 主分類 (Style, Scene, Camera, Character, Clothing, Combined)
    description TEXT NOT NULL,                  -- 模糊自然語言描述 (供語意檢索)
    tags TEXT[] NOT NULL,                       -- 多標籤陣列 (如: ARRAY['cyberpunk', 'rainy night', 'neon'])
    prompt_snippet TEXT NOT NULL,               -- 對應之英文 Prompt 片段
    image_url TEXT,                             -- 範例預覽圖片網址 (為多模態反推預留)
    preset_embedding VECTOR(768),               -- 描述與標籤之綜合向量
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 支援標籤交集/包含查詢的 GIN 索引
CREATE INDEX idx_presets_tags ON prompt_knowledge_presets USING gin (tags);

-- 支援模糊語意檢索的 HNSW 索引
CREATE INDEX idx_presets_embedding 
ON prompt_knowledge_presets 
USING hnsw (preset_embedding vector_cosine_ops);
```

### 3. 系統審計與安全日誌 (`audit_logs`)
由 Semantic Kernel Filters 自動捕捉記錄。

```sql
CREATE TABLE audit_logs (
    id BIGSERIAL PRIMARY KEY,
    session_id VARCHAR(64),
    event_type VARCHAR(50) NOT NULL,            -- Blocked_NSFW, Blocked_Celebrity, TokenUsage
    raw_input TEXT,
    prompt_tokens INT,
    completion_tokens INT,
    latency_ms INT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

## 五、 階段性實作藍圖

```text
[階段一：PoC 核心驗證] ──► [階段二：本地全端與容器化] ──► [階段三：Azure 雲端與 CI/CD]
- 本機 Docker pgvector      - Nuxt 3 介面與打字效果        - GitHub Actions CI/CD
- Agent 自動化資料灌庫      - 入庫確認卡片互動              - Azure Container Apps
- SK 核心編排與安全過濾     - Docker Compose 整合啟動       - 雲端 PostgreSQL 託管
```

---

### 階段一：PoC 核心概念驗證 (Local & Headless)

#### 1. 本地資料庫建置
本機透過 Docker 啟動具備 `pgvector` 延伸模組的 PostgreSQL 實例：
```bash
docker run -d \
  --name prompt-postgres \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=your_password \
  -e POSTGRES_DB=prompt_copilot \
  -p 5432:5432 \
  pgvector/pgvector:pg16
```

#### 2. Raw Data 自動化入庫流程
無需手刻 SQL，透過 Agent 與 Python 腳本協同完成：
1. **蒐集 Raw Data**：將公開詞典文字、爬取之 JSON、或包含圖片連結的資料集中放置於 `scripts/data/raw/`。
2. **Agent 結構化清理**：由 Agent 將原始文字轉換為符合 Schema 的標準化 JSON 格式（拆解出 `title`, `description`, `tags`, `image_url`）。
3. **自動化向量計算與匯入 (`seed_data.py`)**：
   * 讀取結構化 JSON。
   * 呼叫 Gemini Embedding API (`text-embedding-004`) 計算向量。
   * 自動連線本地 PostgreSQL 執行批次寫入。

#### 3. C# / Semantic Kernel 核心服務實作
* **`SafetyGuardrailFilter` (`IFunctionInvocationFilter`)**：
  * 在 Prompt 執行前攔截 NSFW 詞組與知名公眾人物名稱。
  * 命中違規時中斷流程，回傳警示訊息，並寫入 `audit_logs`。
* **`PromptCraftingService`**：
  * 整合 System Prompt，注入「五大維度充足度分析」與「輪次保護邏輯」。
  * 整合 Gemini 1.5 Flash，透過 Swagger 驗證對話推論輸出。

---

### 階段二：本地全端整合與容器化 (Local Fullstack)

#### 1. 前端 Nuxt 3 開發
* **聊天對話視窗**：支援 Markdown 解析、代碼複製按鈕、以及 SSE 串流打字效果。
* **五維度充足度燈號面板**：即時顯示目前 Prompt 在「風格、場景、鏡頭、樣貌、穿著」的充足狀態。
* **定稿與入庫卡片**：
  * 展示最終 positive / negative prompt。
  * 提供「儲存至共享知識庫」按鈕，觸發後端持久化 API。
* **預覽圖片抽屜 (Drawer)**：當 LLM 推薦特定標籤知識包時，使用者可直接預覽 `image_url` 對應的範例圖。

#### 2. 後端端點擴充
* `POST /api/chat/message`：接收使用者對話，執行多輪優化。
* `POST /api/prompts/save-to-shared`：接收使用者確認入庫請求，執行向量化並寫入 `shared_prompt_histories`。

#### 3. Docker Compose 一鍵啟動環境
撰寫 `docker-compose.yml` 同時編排三個服務：
* `db`: `pgvector/pgvector:pg16`
* `api`: 容器化 ASP.NET Core Web API
* `frontend`: 容器化 Nuxt 3 應用

---

### 階段三：Azure 雲端部署與 GitHub Actions CI/CD

#### 1. 雲端基礎架構選型
* **運算層**：**Azure Container Apps (ACA)**。以微服務形式分別託管 Nuxt 前端容器與 .NET 後端容器，支援彈性縮放。
* **資料層**：**Azure Database for PostgreSQL (Flexible Server)**，開啟 `vector` 擴充套件。
* **靜態資產**：**Azure Blob Storage**，存放自行上傳之標籤範例圖片。

#### 2. GitHub Actions CI/CD 流程規劃
建立 `.github/workflows/deploy.yml` 自動化管線：

```yaml
name: Build and Deploy to Azure Container Apps

on:
  push:
    branches: [ main ]

jobs:
  ci-build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      # 後端檢核
      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.0.x'
      - run: dotnet build src/PromptCopilot.Api
      - run: dotnet test src/PromptCopilot.Api.Tests --no-build

      # 前端檢核
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: cd src/PromptCopilot.Frontend && npm ci && npm run build

  cd-deploy:
    needs: ci-build-and-test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Log in to GitHub Container Registry (GHCR)
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      # 建置並推送 Docker 映像檔
      - name: Build & Push API Image
        run: |
          docker build -t ghcr.io/${{ github.repository }}/api:latest -f docker/Dockerfile.api .
          docker push ghcr.io/${{ github.repository }}/api:latest

      # 部署至 Azure Container Apps
      - name: Deploy to Azure Container Apps
        uses: azure/container-apps-deploy-action@v1
        with:
          acrName: ghcr.io
          containerAppName: prompt-copilot-api
          resourceGroup: rg-prompt-copilot
          imageToDeploy: ghcr.io/${{ github.repository }}/api:latest
```
